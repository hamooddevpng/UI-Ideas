# Design 41: Telikom Alive

## Status
Planning brief only for `41.html`. Do not build the HTML in this run.

This is the medium-complexity member of the Design 40 to 42 family.

It must use the exact same high-level homepage structure and content priorities as Design 40. The difference is that every interaction should feel more polished, responsive and alive.

## Difficulty level
**Medium**

The page should be technically achievable with normal HTML, CSS and JavaScript plus a lightweight animation layer, but it should feel much more premium than a conventional corporate website.

## Core idea
Take the clean, reference-backed structure of Design 40 and make it feel physically responsive.

Buttons should react.
Cards should have weight.
Images should reveal elegantly.
Sections should enter with rhythm.
The navigation should feel smooth and intentional.
The quick actions should feel tactile.

The page should feel youthful and premium without becoming noisy or gimmicky.

The motion language should communicate quality, not chaos.

## Non-negotiable shared structure
Designs 40, 41 and 42 must preserve this exact high-level section order.

1. Header / navigation
2. Campaign hero
3. Quick actions
4. Offers / plans
5. Service categories
6. Business and Government
7. PNG connectivity / national impact story
8. Service notices and latest news
9. Help / support / stores
10. Footer

No section should move just to create a different-looking page.

Design 41 is a motion interpretation of the same information architecture, not a different architecture.

## Motion personality
The motion system should feel:
- springy;
- tactile;
- responsive;
- smooth;
- slightly playful;
- premium;
- controlled.

It should not feel:
- cartoonish;
- hyperactive;
- game-like;
- delayed;
- floaty without purpose;
- full of endless looping animation.

## Interaction principles
### 1. Everything acknowledges the user
Hover, focus, tap and scroll should produce a small but meaningful response.

Examples:
- buttons compress slightly on press;
- icon circles spring upward on hover;
- image masks open smoothly;
- nav underline follows the pointer or active item;
- offer panels tilt very subtly toward the cursor;
- section labels slide into place;
- background accents respond slowly to pointer position.

### 2. Motion follows hierarchy
The primary CTA gets the strongest reaction.
Secondary links react less.
Decorative motion stays quieter than functional motion.

### 3. Motion should settle quickly
Most interactions should complete in roughly 200 to 700ms.
Large section reveals can be slower, but the user should never wait for content to become usable.

### 4. No critical content depends on animation
All content should be present and readable even when reduced motion is enabled or JavaScript is unavailable.

## 1. Header / navigation
### Layout
Keep the same content model as Design 40:
- Telikom logo and slogan;
- Mobile;
- Internet;
- Business;
- Offers;
- About;
- Search;
- Support;
- Self Care.

### Motion treatment
- header starts transparent or lightly blended into the hero when safe for readability;
- after scrolling, it settles into a compact solid surface;
- nav underline or highlight glides between items;
- dropdowns open with a short scale and fade using proper origin points;
- Self Care button has a soft spring hover state;
- mobile menu panels slide with depth rather than simply appearing.

### Premium detail
When the header compacts, the logo can scale down slightly while the transition remains crisp.

Do not use a constantly moving navigation background.

## 2. Campaign hero
### Structural rule
Still use one primary campaign, not an automatic carousel.

The hero should have the same functional hierarchy as Design 40:
- label;
- H1;
- short support line;
- primary CTA;
- optional secondary link;
- one strong PNG-relevant visual.

### Motion treatment
Possible hero behaviour:
- headline enters in 2 to 3 short text groups rather than letter-by-letter;
- CTA arrives slightly after headline;
- image mask expands or slides open;
- foreground object or image crop shifts subtly with pointer movement;
- background gradient or soft light responds slowly to cursor position;
- a very light scroll parallax separates text, image and background.

### Bouncy, not childish
Use spring easing for major UI elements, but keep image motion elegant.

The hero should feel like a polished product launch page, not a toy interface.

## 3. Quick actions
### Actions
Use the same primary action hierarchy as Design 40:
- Recharge / Top Up;
- Self Care;
- Coverage;
- Support.

Secondary actions can remain:
- Find a Store;
- Buy SIM;
- Pay Bill;
- Business Enquiries.

### Interaction concept
Turn the action row into a premium tactile dock.

Each primary action can:
- rise 6 to 12px on hover;
- slightly enlarge the icon;
- animate a local background fill;
- spring back after pointer leave;
- compress on tap;
- display a tiny directional cue or descriptor.

### Pointer interaction
Optional magnetic pull should be subtle and limited to the icon or CTA, not the whole panel.

### Scroll entry
Actions can enter with a stagger, but the entire stagger should complete quickly.

## 4. Offers / plans
### Same content model
The commercial content and ordering should remain comparable to Design 40.

### Visual treatment
Use one feature offer plus supporting offers.

Motion can include:
- image reveal masks;
- number / price roll-up if the values are real and verified;
- hover depth using small 3D transforms;
- CTA arrow movement;
- background accent expanding behind the active offer;
- horizontal drag or swipe on mobile only where natural.

### Reactive feature offer
The feature panel may respond to cursor position with a restrained perspective shift.

Maximum tilt should be small enough that text remains stable and readable.

## 5. Service categories
### Structural purpose
Same categories and same role as Design 40.

### Interaction model
Instead of static rows, use a responsive service index.

Desktop idea:
- large service names stacked vertically;
- hovering a service highlights its description and swaps or shifts the supporting image;
- transition between service visuals is smooth and fast;
- a subtle number or icon tracks the active service.

Mobile:
- simple accordion or swipeable service rail;
- no hover-dependent information.

### Motion character
Use soft spring transitions between active states.

This section should feel interactive without changing the underlying service taxonomy.

## 6. Business and Government
### Purpose
Preserve the same enterprise credibility layer.

### Motion concept
Use a large split layout where the visual and copy respond to scroll.

Potential treatment:
- image reveals through a geometric mask;
- solution list items animate a thin line or icon when hovered;
- one infrastructure visual moves at a slightly different scroll speed;
- section heading locks briefly into visual alignment as the image completes its reveal.

Avoid long pinned sections.
The scroll should remain natural.

## 7. PNG connectivity / national impact story
### Purpose
Keep this as the emotional and national layer.

### Motion concept
Use a cinematic but lightweight reveal:
- large PNG photograph enters through a slow crop animation;
- short copy fades upward;
- a restrained line, path or signal motif animates across the composition;
- supporting captions appear as the user reaches them.

Optional:
A subtle signal path can connect multiple small story points as the user scrolls.

Do not fake network data or map accuracy.

## 8. Service notices and latest news
### Structure
Preserve the same two-part practical information layer:
- Service Notices / Important Updates;
- Latest News.

### Motion treatment
Service notices:
- simple slide-in rows;
- soft state change on hover;
- expandable detail if needed.

News:
- image zoom inside masked frame;
- title underline or directional arrow animation;
- cards or rows enter with a short stagger.

Keep the actual reading experience calm.

## 9. Help / support / stores
### Purpose
Make practical help feel easy and immediate.

### Interaction concept
Support options can behave like a responsive command bar.

Possible states:
- hover reveals small descriptor;
- active support option expands slightly;
- map/store icon pulses once when first visible, not continuously;
- chat control springs open into a compact help panel.

### Chatbot
The assistant button can have a soft breathing indicator only if extremely restrained.
Do not create a distracting endless bounce.

## 10. Footer
### Structure
Same content groups as Design 40.

### Motion
Keep footer motion minimal:
- link underline movement;
- small social icon response;
- optional logo or slogan reveal when entering the footer.

The footer is where motion should settle down.

## Visual system
### Palette
Use the same Telikom foundation as Design 40 with richer depth.

Suggested tokens:
- Telikom Blue: `#0875C9`
- Electric Blue Accent: `#249BE8`
- Deep Ink: `#102B3C`
- Soft Sky: `#EAF6FC`
- Ice: `#F5FBFE`
- White: `#FFFFFF`
- Divider: `#D6E4EC`

Optional gradients may be used locally, but avoid full-page blue gradient saturation.

### Typography
Use bold, clean editorial scale.

Motion should support typography rather than distort it.
Avoid text scrambling, constant marquee headlines or letter-by-letter gimmicks.

### Shape language
- slightly more radius than Design 40;
- soft layered surfaces;
- occasional floating panel treatment;
- subtle depth shadows;
- animated masks;
- thin lines and signal-like accents.

## Animation system
### Recommended implementation approach
For `41.html`, plan around:
- CSS transitions for simple states;
- Web Animations API or a lightweight animation library for coordinated sequences;
- GSAP only if it materially improves scroll and spring choreography;
- `requestAnimationFrame` for pointer-linked transforms;
- CSS custom properties for shared motion values.

Do not add a heavy framework just to animate basic hover states.

### Suggested motion tokens
Use consistent timing and easing across the page.

Examples:
- micro interaction: 180 to 260ms;
- UI state transition: 280 to 450ms;
- spring reaction: 350 to 650ms;
- section reveal: 500 to 900ms;
- large image reveal: 700 to 1200ms.

Use a small number of easing curves repeatedly.

### Motion budget
Avoid more than 2 to 3 meaningful animated systems competing within a single viewport.

If the hero has cursor depth, quick actions should not also have large continuous movement at the same time.

## Reactive cursor behaviour
Allowed on desktop only.

Potential uses:
- 2 to 4 degree maximum image tilt;
- small icon magnetism;
- soft light gradient following pointer;
- tiny depth shift in feature offers.

Rules:
- disable on touch devices;
- disable or simplify under reduced motion;
- do not move text enough to affect reading;
- never move controls away from the pointer.

## Scroll behaviour
Use scroll-triggered reveals, but preserve native scrolling.

Allowed:
- fade / translate reveals;
- image masks;
- subtle parallax;
- active section indicators;
- progress accents.

Avoid:
- scroll-jacking;
- long snap sections;
- forced horizontal scroll on desktop;
- multi-second pinned storytelling blocks.

## Mobile strategy
Mobile should keep the premium motion personality without becoming heavy.

Use:
- spring tap states;
- vertical reveal sequences;
- swipeable offer rail if useful;
- compact sticky header;
- large action targets;
- gentle image motion tied to scroll.

Remove or simplify:
- pointer tilt;
- cursor magnetism;
- large parallax layers;
- complex hover-only interactions.

## Reduced motion
This is a mandatory design state.

When `prefers-reduced-motion: reduce` is enabled:
- remove parallax;
- remove pointer-follow movement;
- replace spring movement with short fades or instant state changes;
- stop decorative loops;
- keep all content immediately accessible.

## Accessibility
- keyboard focus must receive an equally polished visual response as hover;
- interactive service states must be reachable without a mouse;
- semantic buttons for state changes;
- semantic links for navigation;
- no information available only through hover;
- minimum 44px touch targets;
- stable layout with no content shift caused by animation.

## Performance target
Design 41 can be richer than Design 40, but should still feel fast on ordinary mobile hardware.

Implementation principles:
- transform and opacity for most animation;
- avoid expensive layout-triggering animation;
- limit large blur filters;
- compress images;
- lazy-load below fold;
- pause observers when not needed;
- do not animate huge full-screen shadows;
- do not use WebGL unless absolutely necessary, which it should not be for this design.

## Relationship to Design 40
Everything a user can find in Design 40 should be found in the same general place in Design 41.

Design 41 should therefore be directly comparable to Design 40:
- same structure;
- same primary pathways;
- same section sequence;
- same approximate content volume;
- much stronger motion and feedback.

## Relationship to Design 42
Design 41 should stop before true 3D scene design and major dynamic hero-state engineering.

It can feel reactive and premium, but it should not yet become a technical showcase.

Design 42 owns:
- dynamic multi-scene banners;
- advanced object animation;
- rotating Starlink hardware;
- richer pointer-follow 3D;
- more complex section-specific visual systems.

## Must avoid
- changing the information architecture just to create novelty;
- automatic hero carousel;
- uncontrolled bouncing;
- making every element magnetic;
- constant background movement;
- excessive glassmorphism;
- slow entrance animations that block reading;
- hover-only navigation on mobile;
- fake statistics;
- motion that reduces clarity.

## Definition of success
Design 41 succeeds if a reviewer sees the same disciplined Telikom structure as Design 40 but immediately feels that the website is more expensive, more responsive and more contemporary.

The ideal reaction is:

"Everything feels alive, but I still know exactly where I am and what to do."
